# Changes view

- **Scope:** while the worktree has a base, a header over the list, 4px 8px 0 padding: a Segmented control as wide as the panel with Uncommitted and Branch, each segment half of it, its label truncating in a narrow panel. Under Branch, 4px under the control, a 28px row 8px in: "Compared to" in 12px `ink-muted`, which never wraps, then the base as a 24px button (12px/500 `ink-secondary`, 6px padding, Inset radius, `raised` and `ink` on hover over 120ms with `--ease-out`, `selected` pressed, tooltip "Base Branch") with a 12px `ink-muted` down chevron 4px after the name, which truncates. It opens a native menu under itself, as the run menu: the default base, then under disabled "Local" and "Remote" lines, each after a separator, the other branches; the base in use carries the check mark. Branch has no checkboxes, More buttons or commit area.
- **Branch:** two groups with the Staged and Changes headings' look, without checkboxes, their names 8px in: Commits, then Files, each with its count; empty they read "No commits" and "No changes". A commit row is a Files tree row: its 12px chevron 8px in (turns like a folder's), 4px after it the subject in `ink-secondary`, which truncates, then the short hash at 11px in the code font and the age ("3h", as a session row's) in 12px, both `ink-muted`; its tooltip is the subject. A click, → and ← open and close it to the files it changed against its first parent, 24px in, on the subject's edge. A file row is the Changes row without its checkbox and More button, 8px in under Files; a click opens its diff in the preview tab, for the branch since the merge base or for its commit, read-only without hunk buttons; the tab's tooltip adds "(Compared to main)" or "(Commit a41c9e2)". ↑ and ↓ move the focus between rows and open a file's diff, as under Uncommitted.
- **Commit:** under the groups: a 1px `line` top edge and 12px padding, its parts 10px apart. First, while the branch has commits its upstream lacks or no upstream and the repository has a remote, the push line: "↑2 to origin/main" in 12px `ink-muted` with the count at 500 in `ink-secondary`, tabular ("First push to origin/feat" before the upstream exists), truncating, then Push at its right end. Then the message card, as the composer in small: `sheet` fill, a 1px `line-strong` border, Control radius. Inside it the message field with no border of its own, 8px 10px 4px padding, Body line height, placeholder "Message", three lines tall empty and growing with the text to eight, then scrolling; Return adds a line and ⌘Return commits; its tooltip is the author git records. Under the text, right-aligned at 11px tabular `ink-muted`, the first line's length as "34/50", `git-changed` past 50, empty while the field is. The card's foot, 4px padding: the Amend toggle (shown while HEAD has a commit) and the Push After toggle (shown while the branch has a remote, tooltip "Push to origin/main after the commit"), each 24px, a 14px icon and a 12px/500 label in `ink-muted`, Inset radius, `raised` and `ink` on hover, `selected` and `ink` while on, over 120ms, and pressing one scales it to 97%; then Commit at the right end, a primary button at 24px with the Inset radius, reading "Amend" while Amend is on, tooltip "Commit (⌘Return)", enabled while the field holds text and a file is staged or Amend is on. Push is the primary button while Commit cannot run, and secondary otherwise, so one blue shows. Amend fills an empty field with the last commit's message, and taking it off empties the field while that message stands unchanged. A running commit or push shows the loading spinner in its button (in `ink-secondary` on the secondary one) and takes no click until it ends. A commit empties the field and takes Amend off; with Push After on, the push follows it. Both read the view and the cards' git counts again when they end.
- **Groups:** the worktree's changed files from `git status`, under Staged (the index against HEAD), then Changes (the file on disk against the index); both groups always show, so an empty one reads its 0 count; under its heading it reads "No staged files" or "No changes" in meta text on the rows' name edge, its checkbox is disabled (a `line` border, no fill). A group's heading is a 28px band across the list's full width: `raised` laid over `canvas`, a 1px `line` hairline along its top and bottom edges, 16px left and 12px right padding, its name at 12px/600 `ink`, then 6px after it the file count at 500 in `ink-muted`, tabular. The group's rows start 4px under it. The heading starts with its checkbox, 8px in, the name 8px after it on the rows' name edge: checked on Staged, where a click unstages every file (tooltip "Unstage All"), empty on Changes, where it stages every file ("Stage All"). Groups sit 8px apart. A heading sticks to the list's top on `canvas` while its group's rows scroll under it, until the next heading pushes it out, as in VS Code. The list scrolls inside with the Files tree's padding, its hover and its focus ring inside the row; ↑ and ↓ move the focus between rows and open each one's diff as a click does, across both groups, Return too, and the selected row scrolls into view.
- **Checkbox:** 14px, Check radius, a 1px `line-strong` border on `sheet`, `ink-muted` border on hover; checked takes an `ink` fill and border with a 12px check in `canvas`, neutral, since a blue box on every row would break the One Blue Rule. Fill and border change over 120ms with `--ease-out`.
- **Row:** a Files tree row in path order: its checkbox 8px in, checked under Staged and empty under Changes, where a click stages or unstages the file and Space does the same on the focused row, then moves the focus on and opens the diff of the next row in the group (the one before when it was last, the file itself in its new group when the group is left empty); the checkbox takes no Tab stop of its own. Then, 30px in, the file name in `ink-secondary` (struck through for a deleted file; it truncates past 70% of the row), 6px after it the folder in 12px `ink-muted` (`ink-secondary` on the selected row), which truncates, then at the right end the lines added ("+12", `success`) and removed ("−3", `danger`) at 11px/500, tabular, each only when not zero, and the status letter at 11px/600 in a 12px column: M modified and R renamed in `git-changed`, A added and U untracked in `success`, D deleted and ! conflicted in `danger`; its tooltip is the status word. The row's tooltip is its path, a rename's as "old → new". The row whose diff the focused tab shows takes `selected` and `ink`. Right of the status letter, 4px from the row's end, a 20px More icon button (three dots, Inset radius, tooltip "More") shows while the pointer or the focus is on the row and takes no room when hidden, so the status letter ends 8px from the row's end and moves in to make room for it; `selected` on hover, as a tab's close button. It opens the row's menu, as right-click does: Stage and Discard under Changes, Unstage and Discard under Staged; a conflicted row, or a pick that holds one, has no Discard, since git cannot restore it.
- **Pick:** a shift-click, or ↑ and ↓ with shift, picks the rows from the last plainly clicked or arrowed row to this one, within its group; a shift-click opens no diff. The picked rows take `selected` and `ink`, in place of the row whose diff the focused tab shows. A picked row's checkbox, Space, More button and right-click act on every picked row ("Stage 3 files" as the checkbox's label). A plain click or arrow picks one row again, Esc drops the pick, and a row that moves to the other group or goes leaves it.
- **Discard:** Discard and a hunk's Discard ask with a confirm sheet first ("Discard Changes?" for one file, "Discard 3 Files?" for more, "Discard Hunk?"), naming the file and its path; then Chord restores the file or the hunk from the index, a staged file or hunk from the last commit, and moves a file git does not track or a staged new file to the Trash (the button reads "Move to Trash").
- **Stashes:** at the Changes heading's right end, a 20px Stash Changes icon button (a box, Inset radius, tooltip "Stash Changes") stashes the staged, unstaged and untracked changes, then shows a notice toast ("Stashed 3 files", a file both staged and changed counting once); it is disabled while both groups are empty. Under Changes, while the repository has stashes, a Stashes group: its heading looks like the others, with a 12px `ink-muted` chevron in the checkbox's place, so the name sits on the same edge, and the whole band is a button (`selected` over `canvas` on hover, focus ring inside) that opens and closes the group, as → and ← do; the group starts closed and holds its state per worktree until the app quits, so 30 stashes cost one row. Open, it lists the stashes newest first, each a Branch commit row with the message in place of the subject, then the branch it came from in 12px `ink-muted` (40% of the row at most, truncating), then the age; git's "WIP on main:" leaves the message. A stash opens like a commit to the files it holds, the untracked ones with U; a click opens the file's diff read-only, its tab's tooltip adding "(Stash a41c9e2)". Right-click on a stash: Apply, Pop, a separator, Drop. Drop asks with a confirm sheet ("Drop Stash?", the message as its detail, the destructive button "Drop"). A failed or conflicting Apply or Pop shows git's message in a failure toast and leaves the stash in the list.
- **Reads:** git is read when the view shows and with each git counts refresh while it shows, so on window focus and every 10 seconds. A failed read shows git's message in a failure toast and keeps the list.
